Docker Compose & .env Generator

Select popular self-hosted applications, configure base paths and environment variables, and get a production-ready stack in seconds.

Guide How to use the Docker Compose Generator & Homelab Guide ▼

Quick Workflow:

  1. Select Your Services: Check the boxes for the self-hosted apps you want in your stack (e.g. Nextcloud, Gotify, Uptime Kuma, AdGuard Home).
  2. Set Configuration & Paths: Specify your root storage directory (default ~/homelab/data) and your server's local timezone (e.g. America/New_York).
  3. Customize Ports & Variables: If a host port conflicts with existing services (e.g., port 53 for DNS or 80 for web), adjust it directly in the service cards.
  4. Export & Deploy: Click Copy compose.yml and Copy .env (or download both). Save them into the same directory on your server and run:
    docker compose up -d

Homelab Best Practices:

  • Keep Credentials in .env: Never hardcode database passwords or API tokens inside compose.yml. Our generator extracts them cleanly into a companion .env file.
  • Port Binding: Binding to 127.0.0.1:PORT:PORT restricts traffic to localhost so you can safely route it via Cloudflare Tunnel or an Nginx reverse proxy without exposing ports to your LAN.

              Home Server Power & Electricity Cost Calculator
            

            

              Calculate true 24/7 wattage, annual electricity bills, and hardware payoff timelines when switching from power-hungry rack servers to energy-efficient mini PCs.
            

          

          
        


        
        

          
            Guide
            How to use the Power Calculator & Energy Optimization Guide
            ▼
          
          

            
Quick Workflow:

            
    
              
  1. Select a Hardware Preset or Enter Measurements: Click any preset chip (e.g. Intel N100 Mini PC, ThinkCentre Tiny, or 2U Enterprise Server) to load baseline measurements, or slide to your exact wall draw.
    2. 
              
  2. Adjust Load Hours: Enter how many hours per day your server is transcoding video, backing up data, or running games. Homelab servers spend 80 to 90% of the day at idle.
    3. 
              
  3. Set Your Local Electricity Rate: Enter your $/kWh rate (US average is ~$0.16/kWh, European rates often range from €0.25 to €0.35/kWh).
    4. 
              
  4. Evaluate TCO & Payoff: Check the Payoff Comparison Card to see how quickly a modern mini PC pays for itself by replacing older enterprise hardware.
    5. 
            

            
Homelab Energy Optimization Tips:

            
    
              
  • Wall Draw vs. TDP: Processor TDP (Thermal Design Power) indicates cooling capacity under synthetic torture, not actual wall draw. A 65W Core i5 can idle under 15W at the wall.
    • 
              
  • Hard Drive Spin-Down: 3.5" enterprise SATA/SAS drives draw 6W to 9W continuously spinning. If your storage array is accessed infrequently, configure spin-down timers in TrueNAS or with hdparm -S.
    • 
              
  • Tune Linux C-States: Install PowerTOP on Proxmox or Ubuntu (apt install powertop && powertop --auto-tune) to allow PCIe lanes, NICs, and CPU cores to drop into power-saving C6/C8 package states.

              Proxmox LXC & VM Resource Sizing Planner
            

            

              Plan hypervisor vCPUs, memory limits, and storage overhead for your self-hosted containers and VMs. Avoid out-of-memory kernel panics and generate ready-to-run pct create shell commands.
            

          

          
        


        
        

          
            Guide
            How to use the Proxmox Sizing Planner & Virtualization Guide
            ▼
          
          

            
Quick Workflow:

            
    
              
  1. Configure Your Proxmox Host Hardware: Enter your physical CPU core count, physical host RAM (e.g. 16 GB, 32 GB, or 64 GB), and storage pool capacity.
    2. 
              
  2. Select Desired Services: Toggle the checkboxes for the workloads you plan to host. Adjust allocated cores, RAM (MB), and disk (GB) to match your workload needs.
    3. 
              
  3. Monitor Resource Gauges: Watch the live RAM commitment meter, vCPU overcommit ratio, and disk consumption indicators.
    4. 
              
  4. Generate Proxmox CLI Command: Select any container from the bottom CLI generator to produce a complete unprivileged pct create command ready to paste into your Proxmox terminal.
    5. 
            

            
Proxmox Sizing Rules of Thumb:

            
    
              
  • LXC vs. QEMU VM: Always prefer lightweight LXC containers for standard Linux tools (Pi-hole, Gotify, Uptime Kuma, Nextcloud). LXCs share the host kernel, eliminating hypervisor virtualization overhead and idling at ~30MB of RAM. Reserve full QEMU VMs for non-Linux OSes (Windows) or systems requiring dedicated kernel modules (Home Assistant OS, TrueNAS).
    • 
              
  • Safe CPU Overcommit: Homelab workloads typically idle 95% of the time. Overcommitting vCPUs up to 2.5:1 or 3:1 (e.g. 24 vCPUs on an 8-core CPU) is standard and safe. Avoid overcommitting cores on heavy database or game server hosts.
    • 
              
  • Proxmox & ZFS Memory Reserve: Never commit 100% of host RAM to guests. Proxmox VE requires ~2 GB for hypervisor services, plus ZFS ARC cache. If physical memory is exhausted, the Linux Out-Of-Memory (OOM) killer will terminate container processes.
